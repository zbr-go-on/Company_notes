### 默认值配置文件路径
根据工程规范，建议存放路径：
```
config/default_values.yaml
```
您可以将所有默认值配置写入此文件，程序启动时自动加载。

## 2. 系统架构
采用分层架构设计，各层职责清晰，低耦合高内聚：

```
┌─────────────────────────────────────────────────────────┐
│                     API 接口层                           │
│  ├─ 批量货源发布接口 POST /transport_order/batch_add     │
│  └─ 单条货源发布接口 POST /transport_order/add           │
├─────────────────────────────────────────────────────────┤
│                     业务服务层                           │
│  ├─ 地址解析服务             ├─ 运费计算服务              │
│  ├─ 货源发布服务             └─ 字段填充/校验服务         │
├─────────────────────────────────────────────────────────┤
│                     数据访问层                           │
│  ├─ 配置读取                 ├─ 数据库操作               │
│  └─ 日志持久化               └─ 结果统计                 │
├─────────────────────────────────────────────────────────┤
│                     外部集成层                           │
│  ├─ 高德地图API              ├─ 运费计算API              │
│  └─ 业务系统发布API                                    │
└─────────────────────────────────────────────────────────┘
```

## 4. 关键设计原则
1. **配置与代码分离**：所有敏感信息（API密钥、数据库密码、Token）通过环境变量管理，所有业务默认值通过配置文件管理
2. **异常统一处理**：所有外部API调用异常、数据库异常、业务异常统一捕获，记录详细日志并返回标准错误格式
3. **幂等性设计**：业务API调用增加幂等性保障，避免重复发布
4. **可观测性**：全链路日志记录，包含请求ID、参数、返回结果、耗时等关键信息
5. **可扩展性**：外部API客户端封装为独立模块，后续更换服务商时仅需修改对应模块
